1. DESIGN SYSTEM DIRECTIVE
═══════════════════════════════════════

VISUAL IDENTITY — dark editorial brutalist, streetwear-zine aesthetic:
- Background: #121212 (concrete dark), secondary surface #1A1A1A
- Primary text: #E5E0D8 (warm beige)
- Accent/CTA: #FF4500 (acid-orange) — used sparingly, only for interactive elements, underlines, and key highlights, never as a background fill for large areas
- Crisp white (#FFFFFF) reserved for headlines only
- Borders: hairline 1px solid rgba(229,224,216,0.15) — no rounded-corner soft-UI, keep corners sharp (border-radius: 0 or max 2px)
- Add a subtle animated/static 35mm film-grain noise overlay (CSS SVG noise filter or a repeating noise PNG at ~4% opacity) over the whole viewport, fixed position, pointer-events: none, so it never blocks interaction

TYPOGRAPHY:
- Masthead/headline font: a bold condensed sans-serif (use "Archivo Black" or "Anton" from Google Fonts if no custom font available)
- Body font: a clean grotesque sans (Inter or Neue Montreal-style) at slightly increased letter-spacing for editorial feel
- Set generous line-height (1.6+) on body copy for long-form readability

LAYOUT:
- High-density editorial grid: asymmetric multi-column layout on desktop (not a centered single-column blog), collapsing cleanly to single-column on mobile
- Smooth, subtle hover states only: slight opacity shift + 1px orange underline reveal on links/cards — no bouncy or scale-heavy animations, this is a dry, confident brand, not a playful one
- Generous whitespace/negative space between editorial sections — density in the grid, breathing room in the margins

TECH STACK:
- Next.js (App Router) + Tailwind CSS + Lucide React icons
- Use a lightweight Node/Express-style API route inside Next.js (app/api/*) rather than a separate backend — keep this a single deployable app
- No unnecessary heavy dependencies — this needs to build and deploy fast

3. SUBSCRIPTION & AUTOMATION ENGINE
═══════════════════════════════════════

FRONTEND FORM:
- Single email input + "Subscribe" button, inline (not a modal) — place one instance on the homepage and one at the bottom of the Issue #1 reader page
- On submit: disable button, show a subtle loading state, POST to /api/subscribe
- On success: swap the form for a success state inline ("You're in. Check your email.") AND trigger the Toast component
- On error (duplicate email, invalid email, server error): show inline error text under the input, do not lose the user's typed email
- Show a small live subscriber-count badge near the form: "Join 15+ Scene Insiders" — pull the actual current count from the backend on page load (see API below), don't hardcode the number

BACKEND — /api/subscribe (POST):
- Accept { email } in the request body
- Validate email format server-side (basic regex is fine)
- Store the subscriber in a simple persistent store — use a lightweight approach appropriate for Replit: either Replit's built-in Database (Replit DB) or a simple SQLite file via better-sqlite3. Do NOT use localStorage for this — that only lives in the browser and won't give a real shared subscriber count. Table/store shape: { email, subscribedAt, source }
- Check for duplicate email before inserting; if duplicate, return a 200 with a message like "You're already in the crew" rather than erroring
- On successful new subscription, trigger the welcome email send (see below) and return { success: true, subscriberCount: <current total> }

BACKEND — /api/subscribers/count (GET):
- Return the current total subscriber count as { count: number } — used by the frontend badge on page load

WELCOME EMAIL SEND:
- Use the Resend API (https://resend.com) for sending — it has the simplest setup for a fast Replit deploy. Install the `resend` npm package.
- Create a helper function sendWelcomeEmail(email) that sends:
  Subject: "You're in. Welcome to Undersole 👟"
  Body (HTML, styled to loosely match the dark/acid-orange brand — dark background email with the orange accent on the button/link):
  ---
  Hey —

  You just joined Undersole, a zine about the sneaker and streetwear scene in India — the resale hustle, the customizers doing wild things in their bedrooms, the culture nobody's writing about properly.

  Issue #1 is live now. Start here → [link to /issue-1]

  No spam, no fluff — just real coverage of a scene worth taking seriously.

  — The Undersole team
  ---
- Call sendWelcomeEmail(email) from inside /api/subscribe immediately after a successful new-subscriber insert. Wrap the email send in a try/catch so that if the email API fails, the subscription itself still succeeds and is still counted — log the email failure to the console but don't fail the whole request over it.

TEST-VERIFY ENDPOINT (dev-only, for process-pack proof):
- Build /api/subscribe/test (POST) — protected by checking a header or query param against ADMIN_PASS — that lets me manually trigger a test subscription + welcome-email send with a hardcoded test email, so I can screenshot the automation firing without needing to use a second real email address. Return a clear JSON response indicating whether the email send succeeded.
